# Technical Constraints — Checkout Platform

> **Synthetic document.** Fictional systems and fictional limits. No real Walmart data.
> Owner: engineering. Created 2026-05-02. Last updated 2026-07-22.

## Payments platform

The payments platform migration completed on 2026-03-20. The authorisation flow was frozen for the duration of that migration. It is no longer frozen and changes to it can ship again.

## Wallet payments

Stored-wallet payments leave our checkout for an external wallet redirect and return only with a result code. The inline recovery pattern cannot be applied to a redirect flow without a change to the wallet integration specification, which is not ours to change.

## Mobile app checkout

The app checkout is a separate implementation on the mobile payments SDK and shares no code with the web payment step. No estimate has been produced for the app implementation.

The app checkout does not emit step-level events. There is no app funnel and no experiment can be run on the app surface until instrumentation is added.

## Delivery slots

Slot capacity is generated by the fulfilment planning service. Checkout can display slots and hold them; it cannot create them. Whether a customer is offered a slot they find acceptable is decided upstream of checkout.

## Data platform

Checkout events land in the warehouse with a lag of up to 6 hours. End-of-day readouts are possible; real-time readouts are not.

## Release calendar

A change freeze applies to all checkout services from 2026-09-07 to 2026-10-05 for peak trading. Anything not released before 2026-09-07 waits until October.
